# Derivation core contract v1

This freezes the storage-neutral stage-1 interfaces for the [0.5.0 plan](plan-0.5.0.md). The implementation is in `src/adam/derivation/`; no command/tool, production model adapter, graph schema or background generation is registered by this increment.

## Development structure

`config.cljs` owns YAML parsing and its local Clojure specs. `core.cljs` keeps selector, evidence and output specs beside the refresh/read behavior that uses them; there are no separate selector/evidence modules or generic validation framework. YAML is a syntax parser, not the domain validator. Specs are normative, and failed checks never attach `explain-data` containing source values.

Each named refresh reads its source snapshot once through the boundary callback. All-config refresh deliberately uses a per-name process boundary: read the first snapshot, finish its model call/outcome, then read the next snapshot. It does not preload every recipe's evidence, and never rereads mutable source state within a named refresh. Selection/role accumulation, fingerprints, sizing and output processing are immutable transformations. Run identity/time are captured before execution; model execution and timeout cleanup are explicit effects. The returned candidate is published only by the later storage stage. Publication's transactional permission/freshness checks are a separate process, not permission to reread mutable state within derivation processing.

## Configuration

`adam.derivation.config/parse-config` accepts YAML 1.2 and returns named compiled recipes in deterministic name order. `config-path` resolves an explicitly supplied absolute configuration root to `adam/derivations.yaml`; host file loading and missing-file disablement are wired in the Pi increment, not here.

- Top-level field: `derivations`, with 1–64 names matching `[a-z][a-z0-9_-]{0,63}`.
- Required recipe fields: positive safe-integer `version`, nonblank `guidance` (at most 64 KiB UTF-8).
- Optional `model`: exactly `provider` and `id`, resolved through Pi's registry/authentication later. Absence means executing-session model. The supplied resolved model must match an explicit override.
- Optional `limits`: positive safe integers `max_input_tokens`, `max_output_tokens`, `timeout_ms`. Output defaults to 8192 and is clamped to the model's supported maximum; timeout defaults to 300000 and cannot exceed Node's native timer maximum, 2147483647 ms.
- Optional `categories`: named entries containing only nonblank `guidance` (at most 8 KiB each); at most 64 categories. When present/nonempty, output categories must be among them.
- Optional `evidence`: `require_supporting_memory_ids` may only be true; `inferred_min_distinct_occasions` is positive and defaults to 2.
- Optional `scope.distinguish`: a nonempty unique subset of `personal`, `repository`, `group`, `session`; default is all four.
- Optional `conflicts.policy`: only `retain_and_highlight` is supported.

A configuration is at most 256 KiB UTF-8. Unknown fields, duplicate keys, multiple YAML documents, aliases, unsupported tags and invalid types/limits are rejected with sanitized errors. There are no inline credential fields, executable YAML tags, repo-local overrides or silently ignored options. These are configuration/parser safety bounds, not a memory-corpus sampling limit.

## Requests and selectors

`core/refresh-configured!` accepts a request map with optional `name` and at most one of `repository`, `session`, `language`. The eventual host command tokenizer must preserve argument values; this core accepts structured requests, not an ad-hoc shell parser.

- Git origins normalize through Adam's existing credential-stripping remote normalization. SSH/HTTPS equivalents select the same bucket. Public selectors require Git remote URL/SCP syntax; ambiguous bare shorthand such as `foo/bar` (or canonical host/path) is rejected before loading evidence. Canonical host/path is accepted only in trusted memory rows. Repository filter matching normalizes both the selector and the source session's `WORKED_ON` origins supplied in the snapshot (raw remotes or canonical host/path), not inferred applicability. Serialized memory origins are credential-stripped canonical values.
- Session requires the full `urn:adam:session:<user>:<pi|claude-code>:<session>` identity. Ownership/access is checked separately, never implied by this string.
- No filter normalizes to `{type: none}` for refresh.
- Language names are case-insensitive; aliases normalize to canonical names. File extensions are matched case-insensitively in the final basename of verified linked repository-relative paths, never memory prose. Extensionless names such as `go`, `c` or `rs`, and dotted parent directories, do not count as extensions. Reflections receive linked paths through supporting observations in the later graph adapter.

Historical supporting observations can accompany selected reflections as provenance, not independent candidates.

`core/normalize-read` accepts the same optional selector/name fields plus boolean `history` (default false) and integer `limit` (default 10, maximum 20). No read filter means list matching buckets of all filter types, **not** just the unfiltered bucket. There is no caller-supplied identity/provider/generation field. The read tool's fixed output envelope will be at most 200 lines or 12,000 UTF-8 bytes, with explicit omission/truncation metadata; implemented shared paging/rendering is described in stage 4 below. Schema normalization already rejects unknown and combined selectors.

## Trusted normalized evidence seam

The future graph/host adapter supplies the configured `reader-id`, direct grants and unique normalized memory rows. It must obtain ownership and source facts from the graph/authoritative entries, not from caller arguments or claims inside memory text. Source IDs are canonical stable graph identities in production; synthetic tests use opaque fixture IDs.

Memory rows contain `id`, `owner-id`, `session-id`, `kind` (`observation`/`reflection`), `producer`, `content`, optional `dropped?`, source entries/contexts, repository origins/IDs and linked paths. Reflections additionally have canonical `supporting-memory-ids`. Source content remains nonblank opaque text, including terminal control characters; JSON serialization escapes them rather than rejecting or altering the memory. Its bound is complete-request context sizing, not the identifier/guidance text spec. This core does not query Neo4j, discover users or infer ownership from prose.

Direct grants contain `owner-id`, `reader-id`, `permission: "read"`; grants do not reverse or transitively expand. Authorization precedes selector matching and serialization. Dropped observations are not candidates; a selected reflection expands its observation supports. Missing/unauthorized support fails closed rather than silently weakening the evidence.

### Source occasions

`source-occasions` contain verified `{session-id, stream-id, entry-id}` anchors for the original activity, not the memory recording entry or a generated summary. A fork/import may retain an original-session anchor different from its recording session; adapters must verify that origin, not relabel a copied prefix as fresh activity. Host adapters must resolve shared user-request/activity anchors so tool-call/results and repeated summaries of one activity share an occasion. Subagent handbacks and compaction summaries are not fresh user confirmations; adapters must carry the original activity anchor where resolvable.

The pure core unions `(source-kind, original host session ID, stream ID, entry ID)` anchors of supporting observations, expanding reflections. The canonical session's ownership namespace is excluded from independence counting so copying the same physical host event across users does not manufacture repetition; authorization still uses full canonical memory/owner identities. Distinct occasions in one session strengthen an inference; repeating the same anchor does not. Missing/unresolved anchors contribute zero, never fabricated independence. Stage-2 graph loading verifies these anchors against retained native Pi/Claude raw records. Citation strings alone are never evidence of independence.

### Comparison and completeness

One optional prior-run snapshot supplies `id`, `input-memory-ids`, `conclusions`. All original dependencies must resolve and be authorized before comparison text is serialized. Nonempty conclusions cannot claim zero dependencies. Prior conclusions must satisfy the closed conclusion spec, with known string basis/scope enums normalized to keywords. Every supporting or conflicting memory ID must occur in the prior run's declared `input-memory-ids`; incomplete declarations withhold comparison rather than silently reducing inherited permissions. The same completeness spec protects cache reuse and saved-result freshness. If comparison is unavailable (including malformed comparison-only source rows), omit its text, report `comparison-unavailable`, and permit a fresh source-only derivation; do not expose private content or block remaining authorized evidence indefinitely.

Roles are explicit: `evidence`, `historical-support`, `comparison-dependency`. The dependency union covers all three, but inherited comparison dependencies do not become new source support or independent occasions. Comparison payload is minimized to known conclusion fields; unrelated prior-run metadata is never forwarded. Recorded IDs/hashes/roles permit later rebuild-safe relationship repair and revocation checks.

## Separate request and sizing

`core/prepare-refresh` takes a compiled recipe, normalized filter, trusted evidence context and a resolved model with `provider`, `id`, `context-window`, `max-output-tokens`. An injected synchronous `measure-input(payload, model)` receives the **complete serialized payload**, including guidance, schema, source content/provenance and authorized comparison conclusions, plus credential-free resolved model capabilities; it must return a nonnegative integer count/bound for that model. No stored producer token count or current Pi conversation substitutes for request sizing.

The stage-1 arithmetic reserves the effective output allowance plus 1024 provider-envelope headroom tokens. The input cap is the smaller of remaining context and an optional configured input cap. Model-aware tokenization/conservative measurement and verification of sufficient provider headroom are the real Pi adapter's responsibility in stage 3; this fake-executor stage does not claim to certify token counts for any hosted model. No real tokenizer/provider is installed here.

Oversized input raises `input-too-large` with measured/available counts and actionable scope/budget guidance before execution. Sequential configured refresh retains those validated numeric counts in the named failure result, but never arbitrary exception data or provider messages. Invalid measurement fails. There is no truncation, sampling, batching or automatic retry. Effective limits and measured input are recorded separately from the requested recipe.

## Output and fake-executor seam

`core/output-schema` describes the provider's wire format, not a schema-library validator. Local Clojure specs enforce closed output objects, classifications and context-dependent source/scope/link constraints. `decode-response` parses JSON with exactly `conclusions` and `links` and takes the completion reason separately from trusted executor metadata. Model JSON cannot claim its own successful finish reason.

A conclusion has:

```json
{
  "id": "local-output-id",
  "content": "A scoped, evidence-bearing conclusion",
  "category": "architecture",
  "basis": "explicit",
  "scope-type": "personal",
  "scope-subject-ids": ["<canonical-subject-id>"],
  "supporting-memory-ids": ["<selected-source-memory-id>"],
  "conflicting-memory-ids": []
}
```

`basis` is `explicit`/`inferred`; subjects match the configured scope. Personal/session/repository have one supplied subject; groups have at least two distinct supplied users. Comparison-only subjects cannot manufacture new source-supported scope. Conclusion content is bounded to 64 KiB UTF-8; original source memory content is governed by aggregate request/context sizing, not a protocol-v1 per-item cap. Support is nonempty, unique and selected; conflict citations can refer to source evidence/historical support, never inaccessible or invented records. Inferred conclusions must meet the verified occasion threshold. These structural rules do not prove semantic truth or whether an explicit request actually corrects another; evaluated interpretation remains required.

Links have `relation` (`contradicts`/`supersedes`), `from` and `to`. The origin is a new local conclusion. Contradiction can target another new conclusion or an authorized prior one; supersession targets a prior conclusion. Subjects and scope must match, self-links and unknown targets are invalid. Interpretation must distinguish a genuine correction from mere recency.

An injected executor receives model metadata, payload, output limit, timeout and AbortSignal, with no tools or session history. It returns normalized `{finish-reason: stop, conclusions, links}` (keyword values internally). Non-stop/truncated, malformed, unsupported or ungrounded output is rejected. A complete empty result is valid.

`refresh!` makes at most one executor call, requests abort on timeout and yields a completed candidate run only after validation. It does not publish anything or implement cross-process locking; graph publication/leases are stage 2. `refresh-configured!` loads and processes selected recipes sequentially, continuing after independent failures and reporting sanitized reason codes, never raw provider errors. Unknown named configurations fail before loading/execution.

## Identity, snapshots and freshness

Version-1 fingerprint encoding is recursively key-sorted JSON; sets/unordered evidence lists are sorted, memory rows sort by ID. SHA-256 is applied to UTF-8 bytes. This is an internal derivation snapshot encoding, not a producer memory-protocol envelope or an imposed JCS requirement.

- Derivation ID: `urn:adam:derivation:<SHA256([reader-id, name, normalized-filter])>`.
- Run ID: `urn:adam:derivation-run:<fresh-UUID>`.
- Conclusion ID: `urn:adam:derived-observation:<SHA256([run-id, local-output-id])>`; local link targets are rewritten accordingly.

Input fingerprints include the selected source state and scope, not the newly generated comparison result. Per-dependency fingerprints/roles cover comparison inheritance for access/freshness. Configuration fingerprints cover the compiled recipe and internal policy version (currently 1); the resolved model key participates separately in refresh reuse. Bumping the policy version makes prior results outdated without changing stable derivation identity. Runs retain requested configuration/effective-limit snapshots, generating provider/model, dependency IDs/hashes/roles and comparison-run provenance, not copies of original memory content.

A cache is reused only if its derivation identity and source/configuration/model match, dependency completeness/authorization holds and dependency fingerprints match. Invalid requesting identities and malformed saved dependency declarations are `unavailable`, not merely outdated. Successful empty results are reusable; input ordering does not create a new call. `freshness` is evaluated in the original derivation identity context: changed source/configuration is `outdated`, missing/unauthorized dependencies are `unavailable`, and the current session model alone does not make a saved run stale. Cross-reader query visibility and graph-owner traversal are implemented and tested in stage 2, not inferred from this pure helper.

Latest publication is a graph concern: a completed run remains a candidate even if its inputs changed mid-call; the later publisher records latest-but-outdated rather than retrying. No core callback writes sources, producer records, graph nodes, locks or Pi boundary drafts.

## Validation boundary

Normal tests exercise the configuration and refresh/read interfaces using synthetic rows and fake executor/measurement callbacks. Parameterized cases cover evidence, sharing, comparison and selectors end to end; seeded `test.check` properties cover YAML round trips, origin equivalence and input-order invariance. `test.check` is a compiler/test dependency, not a runtime requirement. This stage requires no live Neo4j, real model, inherited credentials or production mutations. Source-occasion extraction, provider certification, production commands and MCP registration remain later work. The stage-2 storage boundary below is used by explicit Pi generation and stage-4 saved reads.

## Concrete graph boundary (stage 2)

`adam.derivation.store/with-driver` captures a host-resolved principal and database. No operation accepts a caller-supplied reader. `ensure-schema!` explicitly creates the three derived-label uniqueness constraints and native-entry index. Stage-3 Pi initialization is command-only and requires interactive approval when readiness fails. Every write checks those actual constraints through `SHOW CONSTRAINTS` before data operations and fails with `schema-unavailable` if any are missing. `check-schema!` requires all three constraints plus the online `AdamEntry(entryId)` index. Successful prior initialization is not cached as permission to write after constraints disappear.

`acquire-refresh!`, `renew-refresh!` and `release-refresh!` use a per-derivation server-time lease, not the notification-worker lease. Lease windows are explicit safe integers from 1 ms through 24 hours, with renewal for longer work. Token allocation precedes transaction retries. Lease durations are transmitted as Neo4j integers so stored deadlines remain integers. Busy, unavailable and fenced outcomes are content-free.

`publish-refresh!` takes a named selector, live token and complete validated core candidate. Closed specs validate run identity, configuration/model snapshots, fingerprints, role completeness and conclusions before opening a session. Creation times use canonical UTC with exactly three fractional digits (`Date.toISOString`), making chronological string ordering unambiguous; invalid calendar dates are rejected. Comparison-dependency roles require a non-null comparison-run ID. Saved diagnostic enum values normalize on decoding, including `comparison-unavailable`. Transactional ownership/grant checks cover **every** declared input, including unreturned evidence and inherited comparison dependencies. The original compared run must belong to this derivation, have complete inherited dependency roles and remain authorized. Comparison-only inputs cannot become new support/conflict evidence. Links require compatible authorized endpoints.

Publication creates the run, conclusions, source dependencies and optional contradiction/supersession relationships and replaces `LATEST_RUN` in one token-fenced transaction. Empty successful runs retain history. Constraint or permission failures roll back all publication writes; failed attempts create no completed run and the caller must release its token or allow expiry. Stage-3 controllers must release their own token in failure/cancellation cleanup, including publication rejection, and preserve prior results when release itself fails. A crash may leave the last attempt recorded as `refreshing`; status must consult the deadline rather than claiming expired work is still active. No model work occurs inside transactions, and original memories/session state are never changed. The candidate's processed fingerprints are retained even if source content changed; `available` below is **not** a current-freshness claim.

`read-runs!` accepts the frozen read request and returns `{items, truncated?}`. Reads default to latest across matching filter buckets; explicit history is bounded to 10 rows by default, at most 20, with a one-row omission probe. Each available item contains name, normalized filter and the saved run. Denied items expose only run ID and `unauthorized` or `unresolved-evidence`, never conclusion/configuration text. Every read resolves current one-hop read grants, unique source-session ownership and all recorded inputs; recorded IDs, actual source relationships and conclusion properties must remain complete. Revocation applies to latest and history without regeneration.

`repair-dependencies!` explicitly rebuilds `USED_MEMORY`, `SUPPORTED_BY` and `CONFLICTING_EVIDENCE` from stored stable IDs for the bounded matching history page, returning per-run repair/denial outcomes and `truncated?`. It captures all candidate/dependency state before writes, denies unresolved/unauthorized records without mutation, and does not generate or alter source records. Recreated source nodes with the same IDs remain unreadable until the repair restores complete links. Large-history pagination and host scheduling remain later integration work; truncation must not be represented as whole-history repair.

`runJson` is the authoritative immutable dependency-role record. `USED_MEMORY.roles` stores the sorted role names for graph-level provenance and is reconstructed during repair; missing or altered cached edge roles never reduce the recorded authorization requirements. Memory ID lookups rely on source-foundation `AdamObservation` and `AdamReflection` uniqueness indexes. Disposable Neo4j 5.26 EXPLAIN of the four affected complete queries (including seven memory lookup occurrences) uses both label-specific unique index seeks, not memory label/all-node scans; no speculative query rewrite is required.

`load-input!` loads principal-bound, read-only generation inputs in a single read-committed transaction; this is not a consistent cross-query snapshot. Concurrent commits may change evidence or access between queries; publication reauthorizes all dependencies and processed fingerprints record what was used. It validates a named selector before opening a session, loads all own/directly granted memories without a LIMIT or file requirement, includes dropped support records, and preserves source/recording, session repository and linked-file metadata. Reflection support IDs come from actual SUPPORTED_BY observation nodes. Declared producer-local support IDs must agree with those nodes' memoryId, effective producer and unique owning session; missing or mismatched supports deny loading. Blank Pi producers use the same pi-observational-memory normalization as graph retrieval. Reflection linked paths include supporting observations' ABOUT paths, including retained dropped supports; a dropped flag on a reflection is not an observation tombstone. Ambiguous ownership, inconsistent host identity or malformed supports deny the entire load, including unrelated recipes. All loaded rows are validated before rejection; invalid-source-count reports the exact number of structurally invalid ownership/host/support rows, without IDs/content. Valid rows are not partially returned when this count is nonzero. Cypher first resolves the reader and direct incoming read grants, then expands only those owners' memories; DTO grants reflect that query authorization, not an independent permission check. Repository metadata reads the persisted normalizedOrigin field. Configured refresh passes the original raw selector plus the resolved recipe name to the loader, while keeping normalized filters and recipe guidance in pure core processing. This avoids lossy normalized-origin-to-raw-selector conversion. Recipe filtering and complete-request sizing remain pure core responsibilities. The previous latest lookup is restricted to the exact normalized derivation identity, not the latest arbitrary filter bucket; unavailable prior text is withheld. There is no model work or graph write in this boundary.

Source-activity verification reads retained raw entries once per distinct authorized source session and its same-owner fork lineage before pure processing. This correctness-first implementation loads full source-session entry sets, not incremental anchor caches; raw transcript text never enters model payloads or saved derivation evidence. Records are JSON-parsed individually into compact walker fields: IDs/parents, role/type, user-only bounded marker text, origins/flags and tool identity links. Non-user message text and tool-result payloads are not retained. Payloads/attachments/arguments and unrelated nested fields are discarded; only SHA-256 of the exact raw UTF-8 record is retained for fork-copy comparison. The graph result's entries array is not wholesale converted to persistent maps, and compact sources drop the raw entries reference. The initial response contains source metadata only. Entries are then consumed through Result.subscribe, one authorized source session at a time, with a moderate 100-record fetch batch for input-read sessions (including their non-entry queries), avoiding one network round trip per record. Other store sessions retain driver defaults. Each callback immediately extracts compact fields and hashes, without awaiting or accessing Result.records; partial stream errors reject the entire load and close the session. The first failure clears partial compact state and disables later callback processing/indexing; subscribe itself has no cancellation API, so already delivered rows may still arrive until transaction rollback/session closure. Entry queries recheck the exact captured owner and require single ownership, so ownership drift yields no anchors. This avoids retaining an all-transcript raw response. Compact indexes still grow with entry count, and a single raw record must fit in memory: this is not a fixed total-heap guarantee or a new record-size limit. Production refresh latency has not been measured. Source records must match native IDs and Claude session/child-stream identity. Native user requests anchor their assistant activity; uniquely matched tool calls/results share that anchor. Claude sibling fragments resolve through request IDs, and compaction logical ancestry carries the original occasion without counting summaries as confirmations. Child activity resolves only via a uniquely matched structured Agent tool result/agent ID; handback prose cannot invent confirmations. Same-owner fork copies with verified lineage retain the oldest byte-identical original request locator. Claude Code forks reuse UUIDs while rewriting sessionId; native main-stream request UUIDs present in multiple distinct host sessions within the reader's directly authorized ownership scope contribute zero, including cross-owner fork copies and memoryless origins/copies. Identical host session IDs in different ownership namespaces remain one occasion under core deduplication. Unauthorized copies cannot affect the result. Detection uses an AdamEntry(entryId) range index and does not send tool-result-only/summary/injected UUIDs as candidates. Unmirrored origins cannot yet be detected; source verification must be repeated as replicas arrive. Missing/ambiguous origins, cycles, malformed records and unmatched results contribute zero, not fabricated occasions. Known task/teammate notifications, local command output and interrupted-request markers contribute zero. When present, Claude turnOrigin is restricted to human/sdk; promptSource is secondary and restricted to typed/suggestion_accepted/sdk, while userType must be external. Unknown, malformed, system/task_notification or non-external origins yield zero. These interactive tuples come from a review-reported, content-free aggregation of 17 local transcripts, represented by explicitly synthetic fixtures; SDK/external also has the native characterization fixture. suggestion_accepted is treated as a native request from a human action on model-proposed text, not as a typed preference endorsement. A recognized origin requires turnOrigin or promptSource: userType external alone does not establish one. Both <command-message> and <command-name> forms are eligible native requests with recognized structured origin, not preference endorsements. Without such origin they are ambiguous command echoes and contribute zero. <bash-stdout>/<bash-stderr> are output and always contribute zero; <bash-input> is a typed request only with recognized human/SDK origin, otherwise ambiguous and zero. Unverified message source/origin guesses are not used for Pi classification. Image/document-only native requests remain occasions; empty text blocks do not. Pi sendUserMessage uses extension source at the prompt-input boundary, but that provenance is not reliably retained in ordinary message JSONL; unmarked relays remain indistinguishable native-request locators. Native-request identity is provenance, not proof of a human endorsement; the model must still distinguish attributed corrections from unendorsed assistant choices. Explicit Pi generation uses this storage boundary. Stage 4 registers explicit saved-result reads in both hosts, described below. Stage-4 provenance must read authoritative dependency roles from runJson, never infer them from informational edge roles. If schema is lost, failure release cannot write either; recovery requires restored constraints or lease expiry. The schema check currently targets the supported Neo4j 5.x constraint vocabulary; a future Cypher-25/2025.x upgrade must validate its renamed node-uniqueness type before cutover.

## Stage 3: explicit Pi generation

`/adam:derive [name] [--repository origin | --session urn | --language language]` parses the frozen selector before graph/model work and reads the one user-wide YAML file. The bounded no-follow regular-file reader loops through short reads to EOF, rejects over 256 KiB and invalid UTF-8, and sanitizes diagnostics. Platforms without safe `O_NOFOLLOW` support fail closed for YAML generation (currently Linux/macOS supported); other host surfaces are unchanged. Unknown names fail before idle waiting. Bare refresh dispatches all names in sorted order with independent outcomes through the same core sequencing adapter used by synthetic contract tests.

Generation resources start only on the command. The registry resolves/authenticates the default session model or named override before graph access; no credentials enter capabilities, YAML, request/run metadata or diagnostics. First use checks the three constraints and online native-entry index. Missing readiness requires interactive confirmation before once-per-process schema setup and bounded index waiting; cancellation or failure is not cached. Noninteractive hosts cannot approve missing schema. Subsequent refreshes verify readiness without DDL; writes independently recheck constraints.

The provider adapter separates fixed instructions, schema and validated recipe into `systemPrompt`, with selected source memories/provenance, exact output eligibility data and authorized comparison in the sole user data message. Host/source-derived identifiers remain data, not higher-trust system instructions. The prompt states exact subject cardinality/ID vocabularies, eligible supports/conflicts, category syntax/configuration, verified-occasion inference thresholds, compatible-scope link rules and prior-only supersession. Output rules enumerate authorized subject/evidence IDs and deduplicated verified occasion keys; this intentionally duplicates some provenance for clarity and is included in complete-request measurement. Cross-user disagreement is expressed through separate attributed conclusions/conflicting evidence, never a cross-subject link. Policy version 2 stales older runs without changing identity or history. Validation uses the same closed specs as before, exposing only approved content-free reason keywords (including JSON/wire/block/size/incomplete failures), not rejected content or IDs. Tools are empty; conversation, session-affinity ID and host tools are absent. `maxRetries=0` and `cacheRetention=none` are explicit. Output is strict raw JSON, not fenced markdown. All non-success finish reasons are failure codes accepted by release cleanup.

Pi owns model/provider compatibility, authentication and transport: Adam has no API-name allowlist. Shared measurement counts the constructed system/data UTF-8 bytes conservatively; the resolved model must match measurement/execution. Core reserves 1024 framing tokens plus the complete output allowance and rejects oversized complete inputs without sampling. This may overestimate English input several-fold. It is not a tokenizer or blanket certification of arbitrary custom provider transforms/proxies; provider context failures reject the refresh without publication. Verified Codex framing sends these instructions/data without a large additional preamble. Provider quality/capacity certification is evidence-specific, not implied by accepting an API name.

Output-token limits are requested through Pi where supported, not universal server-side or spending guarantees. Pi 1.1.0 Codex does **not transmit** maxTokens as an output cap; neither visible output nor reasoning tokens receive that server limit. Reasoning-capable models request minimal effort. Known budgeted Anthropic models still require an allowance of at least 2048: subtract 1024 from the SDK answer allowance and request a 1024 minimal thinking budget. These are request settings, not guaranteed billing ceilings. Token/cost usage may count against subscription limits rather than per-token charges.

Accepted generated JSON text is bounded to **1 MiB UTF-8 before parsing**, independently of token settings, with existing structured/scope/support validation and non-success completion rejection. Thinking blocks are discarded, not parsed or stored. The acceptance cap does not bound thinking allocation, accumulated SDK streaming buffers or billed generation. The configured timeout requests cancellation, not immediate server cessation. Failure, truncation, oversized/invalid output or cancellation preserves prior results.

A 60-second independent derivation lease renews every 20 seconds while loading, generating and publishing. Lost/fenced renewal conservatively aborts work, including pre-execute gating after input load. No model runs inside retryable graph transactions. Failure/timeout/cancellation releases the token after outstanding renewal and preserves prior latest; failed release leaves expiry as recovery. Successful cache completion rechecks token/expiry, byte-identical latest run and complete current dependency authorization transactionally, without a new run. `reused` is not a freshness guarantee: stage-4 reads must recompute fingerprints and authorization, including mid-refresh changes.

Pi awaits explicit command handlers; input loading/model work can occupy the invoking window. The command deliberately ignores `ctx.signal`, which belongs to an unrelated agent turn, and supports shutdown cancellation plus its configured model-call timeout. Shutdown aborts active work and awaits cleanup before closing the shared replica driver. Cleanup may wait for graph-driver timeouts; abort does not guarantee immediate provider/billing termination. Lifecycle handlers never call generation, and derivation failures do not change replica health.

Normal interface tests use synthetic inputs, a fake registry/executor and schema/lease operations. Disposable live tests use principal-bound storage and the packaged Pi boundary with a fake provider, proving successful runs, empty reuse, truncation/failure preservation, token clearing and exact test-resource cleanup. No production access or real model call is implied. Stage 4 provides saved-result rendering and Pi/Claude read-only adapters. Real-provider acceptance remains separately gated.

## Stage 4: saved-result reads

`/adam:derivations [name] [--history] [--limit 1..20] [one --repository/--session/--language selector]` and `adam_derivations` share `adam.derivation.read/execute!`. Validation precedes configuration/storage IO. YAML uses the same bounded no-follow reader as generation; missing configuration yields `not-configured`, while malformed/unreadable/unsafe configuration yields `invalid-config`, without raw errors. An absent recipe does not prohibit authorized saved content, but its freshness is unavailable. No input selects a reader identity. Pi/MCP registration is inert and conditional tool registration follows Neo4j configuration.

`store/read-snapshot!` opens one read-committed transaction, loads a bounded latest/history page, validates all run dependencies, and only for available results checks the ONLINE RANGE native-entry index and loads complete authorized generation-compatible memory/anchor inputs. It does not create schema, generate, repair or modify graph/source data. After potentially long streaming, it reauthorizes the page before returning content. Full role completeness comes from immutable runJson, not cached relationship role properties. Support metadata contains canonical source/producer/session/stream/entry locators, not source contents or raw transcripts. Missing support metadata is visibly `provenance unavailable`.

The shared renderer compares each available run against the current recipe and complete evidence, including historical runs; history is not represented as fresh merely because its own snapshot is internally coherent. Model-only changes do not stale results. Unavailable/unauthorized runs return status without conclusions or provenance. Successful empty outcomes are displayed. Free-form content, IDs, metadata and subjects are JSON-quoted to prevent multiline/control-character heading spoofing. Scope, model, supporting/conflicting evidence, dependency roles and scoped correction/contradiction links are shown explicitly; these are not automatic instructions. Both hosts use the same 200-line/12,000-UTF-8-byte ceiling, with item/line/byte omission flags. MCP declares a strict outputSchema for status, result-count, truncated?, configuration-available? and configuration-status; code-only error results have isError.

Full freshness can stream the entire authorized retained source corpus even for one result or a narrow selector. Compact indexes remain O(entries), individual records must fit memory, and latency is unmeasured on production. A process-wide single-flight gate shared by command/tool rejects overlapping reads with content-free `busy`; it releases only after cancelled work and the first session close have settled. Pi tool and MCP request AbortSignals close sessions/cancel Result subscriptions and stop callback parsing. Pi command/shutdown owns a cancellation controller rather than adopting an unrelated turn signal. Shutdown aborts/awaits reads before closing their pool; MCP stdin shutdown also aborts saved reads. Driver cleanup may wait for timeouts. Neo.ClientError.Transaction.TransactionTimedOut* is sanitized to `read-timeout`; no raw driver message is returned. Filters currently do not narrow full-source verification.

The read adapters deliberately use a separate lazy principal-bound raw query pool to avoid side effects from the replica's initialize/migration path. No derivation dependency is added to the worker runtime. Synthetic interface/adversarial tests and disposable Neo4j prove current/changed/history/empty reads, mid-stream grant revocation, source relationship loss/explicit repair, cancellation/busy behavior, bounded output and compiled Pi/MCP parity without model calls.
