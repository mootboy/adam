# Distinguish parked archive rejections from retryable repair failures

- Status: proposed
- Category: enhancement
- Created: 2026-10-02
- Owner: unassigned

## Problem

PR #23 counts malformed or unsafe parked snapshots into repair `failed`. Consequently, every `worker.js --once` exits nonzero and Pi reports reconciliation deferral until an operator repairs/removes the file, even if all eligible work succeeded. This makes an operator-action rejection indistinguishable from a transient backend or processing failure.

## Outcome

Explicit repair clearly separates retained archive rejections from retryable failures, without implying rejected snapshots were ingested or recovered.

## Scope

### Included

- Add a separate `parked-rejected` diagnostic count for malformed/unsafe archived snapshots.
- Surface the count and operator-action meaning in Pi status and standalone repair diagnostics.
- Exit successfully from `worker.js --once` when only archive rejections remain; do not describe that state as transient Pi deferral.
- Preserve rejected snapshots for operator repair, with owner-only/no-follow handling and content-free diagnostics.

### Excluded

- Automatic deletion, rewriting, requeueing, or repair of rejected snapshots.
- Changes to sidecar rejection/conflict semantics, source ownership, recovery ordering, or lease scope.
- Archive retention policy, producer/model implementation, version or release changes.

## Acceptance criteria

- [ ] Malformed and unsafe archived entries increment `parked-rejected`, not retryable `failed`, and remain untouched.
- [ ] Rejection-only explicit repair exits 0 and reports operator action; Pi shows the count without transient deferral.
- [ ] Mixed rejection and real backend/projection/requeue failures still exit nonzero and retain retryable work.
- [ ] Healthy locators recover despite unrelated rejected entries.
- [ ] Busy lease and unsafe/unreadable archive-directory failures remain visible failures; the implementation distinguishes inability to inspect/process the archive from rejected individual snapshots.
- [ ] Deterministic and packaged CLI/Pi tests cover rejection-only and mixed outcomes without following symlinks or logging raw contents.
