# Long “Working” pause after turns

- Status: done
- Category: bug
- Created: 2026-09-25
- Completed: 2026-09-25
- Owner: unassigned

## Problem

When adam is enabled, Pi appears to remain in the `Working` state for a long time after each request has otherwise completed. Disabling adam appears to remove the pause.

This makes ordinary interaction feel blocked by derived Neo4j replication and indexing even though local session JSONL is authoritative.

## Current evidence

adam registers an asynchronous `turn_end` handler in `src/adam/replica/register.cljs`. The handler returns the serialized synchronization promise, which includes:

1. Neo4j connection and identity initialization when needed;
2. lossless session suffix synchronization;
3. repository discovery;
4. a rebuild of the selected branch’s file-evidence and adapted-memory projection.

Pi treats `turn_end` as an actionable lifecycle boundary and waits for asynchronous handlers.

A live reproduction measured 69,589.2 ms total: 0.1 ms queueing, 123.8 ms initialization, 135.3 ms replica synchronization, 45.4 ms repository discovery, 391.3 ms extraction, and **68,891.3 ms in Neo4j projection**. The projection queries matched `AdamEntry` by `(sessionId, entryId)`, but the graph had 79,594 AdamEntry nodes and no index for those properties. `EXPLAIN` confirmed `NodeByLabelScan` for both TOUCHES and SOURCED_FROM writes.

A read-only matching benchmark over 593 entry IDs reproduced the query-plan cost at 19.5–20.1 seconds per run. Adding a composite `AdamEntry(sessionId, entryId)` range index changed the plan to `NodeIndexSeek` and reduced the same benchmark to 49–76 ms, approximately 260–400× faster. adam now creates that index as part of file-evidence schema initialization.

Instrumentation now retains the latest lifecycle event’s queue wait, initialization, replica synchronization, repository discovery, evidence extraction, Neo4j projection, total duration, and completion timestamp in runtime status and renders it through `/adam:status`. It emits no external telemetry and retains no content or timing history.

## Reproduction

1. Configure a reachable Neo4j instance with `ADAM_NEO4J_*`.
2. Start Pi with adam enabled in a persisted session.
3. Submit a request and measure from completion of the final assistant output until Pi leaves `Working`.
4. Repeat in the same session with adam disabled.
5. Repeat with a short and a large session, recording `/adam:status` afterward.

## Ranked hypotheses

1. **Confirmed — missing projection lookup index:** repeated AdamEntry label scans dominated TOUCHES and SOURCED_FROM writes. A composite lookup index removed those scans and reduced the isolated benchmark by roughly 260–400×.
2. **Still relevant — awaited lifecycle work:** Pi awaits the synchronization promise. After the query fix, a new end-to-end timing will determine whether decoupling routine derived work from the interactive boundary is still necessary.
3. **Rejected as dominant — repository discovery/extraction:** together these consumed under 0.5 seconds in the 69.6-second reproduction.
4. **Not observed — queue amplification:** queue wait was 0.1 ms in the reproduction.

## Outcome

adam replication and derived indexing do not hold Pi in `Working` after every turn. Synchronization remains serialized, eventually consistent, observable through `/adam:status`, and safely drained or closed during shutdown.

## Scope

### Included

- Measure lifecycle, replica, projection, and repository-discovery durations.
- Determine which adam event handlers Pi must await.
- Move non-actionable derived work off the interactive turn boundary if safe.
- Preserve eventual suffix reconciliation and outage isolation.

### Excluded

- Weakening local JSONL authority.
- Dropping lossless payloads or code-memory provenance.

## Validation

Before the fix, live `session-start` synchronization took 69,589.2 ms, including 68,891.3 ms in projection. After adding the composite index, `session-start` took 1,072.3 ms with 367.6 ms in projection. The original interactive path was then verified directly: `turn-end` completed in 881 ms with 356.2 ms in projection and no queue wait.

The isolated 593-entry lookup benchmark improved from 19.5–20.1 seconds to 49–76 ms, and `EXPLAIN` changed from `NodeByLabelScan` to `NodeIndexSeek`. Deterministic validation passed 57 tests with 206 assertions; the opt-in live Neo4j suite passed 24 assertions. Instrumentation is committed in `5fd3d87`; the schema fix is committed in `42bf3f0`.
