# Keep Pi responsive while Adam reconciles long sessions

- Status: done
- Category: bug
- Created: 2026-10-28
- Owner: unassigned

As a Pi user, I want turns to finish and long sessions to open promptly while Adam catches up in the background, without losing durable conversation or memory evidence.

## Problem

On a long conversation, Pi remains in “Working” after the answer finishes. Opening that conversation also takes longer, even though Pi itself starts quickly. Reporter-supplied Adam timings show approximately 13–14 seconds of ordinary reconciliation at both boundaries, with no queue backlog or active migration.

## Before → after

| Same long conversation | Observed before | Required after |
| --- | --- | --- |
| Finish a turn | Adam's awaited turn-end work takes 13.8 seconds | Pi completes the turn promptly; Adam continues reconciling |
| Open the session | Adam's awaited session-start work takes 13.0 seconds | Session interaction becomes available without waiting for Adam's reconciliation |
| Continue typing while Adam catches up | Synchronous scanning/extraction is on Pi's event loop | Reconciliation does not cause substantial UI freezes or replace the spinner with input lag |

**Proposed change:** enqueue serialized, coalesced background reconciliation from normal lifecycle hooks and keep heavy scanning/extraction off Pi's interactive event loop. Moving only network waits behind an unawaited promise is insufficient.

### Baseline code-derived behavior (before this fix)

- `src/adam/replica/register.cljs`: `session_start` and `turn_end` callbacks return promises awaiting `synchronize!`. `synchronize-file!` awaits replica sync followed by file/memory projection. Returning `undefined` after completion prevents boundary-result errors but does not make the work non-blocking.
- `src/adam/knowledge/index.cljs`: indexing synchronously scans the whole JSONL, retains raw entries, selects branch entries, adapts embedded memory, discovers file locators and rebuilds a session-wide projection. Investigate repeated parsing/traversal, allocations and main-thread filesystem work using a long synthetic session.
- `src/adam/replica/jsonl.cljs` and replica synchronization: inspect scanning on the replica path too; removing only projection's main-thread work is not sufficient if replication still stalls the event loop.
- Projection timing includes retained producer-stream reads as well as graph writes. Do not interpret that bucket as write-only database time.

This follows [issue 001](001-long-working-pause-after-turns.md), whose original delay was dominated by a missing graph lookup index and was fixed. The new measurements have a different distribution, dominated by scan/extraction; do not assume the old index defect has returned.

### Implemented architecture

The approved record-carrying queue separates asynchronous reads, pure processing and committed writes. The processor does **not** encapsulate the entire I/O pipeline.

```text
Pi lifecycle hook → capture path/cwd/leaf → enqueue catch-up → return undefined
                                  │
Reader/coordinator: async complete raw records + byte ranges
                                  │
Processing thread: (previous state, explicit inputs) → (next state, write plan)
                                  │
Writer/coordinator: guarded transactions → durable checkpoint acknowledgement
```

- One process-local scheduler coalesces **unread automatic requests**, retaining the latest branch snapshot for each file without crossing an explicit-command barrier. Raw batches are delivered one at a time with backpressure, not accumulated or replaced with a last-line-only event. Source records are never discarded.
- The asynchronous reader and synchronous scanner share the same pure validation fold. One complete validated source snapshot serves both replication and indexing. This first implementation still reads source history to verify prefixes and reconstruct branches; it claims neither suffix-only disk reads nor a persistent cross-job cache. A single large physical record must fit memory.
- The lazy processing thread receives only data, with no inherited credentials/environment or CLI/preload flags. Filesystem, Git and Neo4j operations remain outside it. Repository-boundary probes are asynchronous. Replica plans expose bounded payload batches rather than transferring all entries back at once.
- Read/processed offsets are tentative; only successful store transactions advance durable checkpoints. Failed writes, worker crashes and concurrent appends discard speculative state and can retry from authoritative source. A not-yet-persisted captured leaf rejects the snapshot instead of producing an empty valid projection.
- Source/producer snapshot guards reuse the existing graph session lock and reject stale derived replacement before it can delete newer memory or incoming derivation dependencies. Normal projection errors remain isolated; migration rebuilds require successful projection before advancing their existing marker.
- Ordinary hooks return `undefined` immediately. `agent_settled` also captures the post-boundary leaf after producer drafts persist. Pending foreign notifications wake the existing detached durable-spool consumer, not Claude scanners on Pi's event loop. Explicit import and repair remain awaited.
- Session replacement/reload cancels queued processing promptly. Quit permits final catch-up within a five-second cleanup budget; then outstanding work is cancelled and resources closed. Cleanup is idempotent. Later supported reconciliation recovers from JSONL/checkpoints and Pi's restored selected leaf; there is no new durable queue, daemon or automatic respawn loop.
- Status distinguishes targets/running/pending work and the last synchronized session. Notification-worker wake state distinguishes advisory scheduling from measured drain completion. Errors preserve malformed-session classification without logging record content.

Implementation is local to `replica/background.cljs` (coordinator, thread transport and scheduler), `replica/processing.cljs` (data-only processing), existing scanner/store/planner/repository boundaries and lifecycle registration. `processor.js` is a minimal shim for committed `dist/adam-processor.js`. No dependency, identity/schema version, migration or release transition is introduced.

### Required behavior and implementation scope

- Normal lifecycle callbacks enqueue reconciliation and return promptly without waiting for database initialization, Git discovery, scanning, extraction, graph reads/writes or retries. Preserve Pi's void side-effect callback result contract.
- Capture immutable source/session locators and explicit selected-leaf state when scheduling, including known-null selection. Queued work must not read a later session's mutable context after a switch.
- Preserve serialization and coalesce redundant pending requests for the same source session toward the latest requested state. Do not accumulate a full rebuild per event or silently drop another session's work. In-flight work and later requests must converge on the latest requested branch.
- Avoid long synchronous work on Pi's event loop. Choose an off-thread/process boundary or genuinely bounded yielding/incremental processing based on measurements; do not prescribe a new daemon or generic scheduling framework by default. Extension registration remains inert.
- Preserve lossless append checkpoints, immutable-payload conflicts, branch selection, multi-repository evidence, aggregate producer contributions and stable incoming derivation dependencies. Coalescing may skip intermediate projection snapshots, not authoritative raw records.
- Keep eventual reconciliation after crashes, outages and extension ordering delays. Authoritative local JSONL remains sufficient to catch up on a later supported reconciliation trigger; distinguish desired convergence from already completed synchronization.
- Preserve failure isolation and bounded warning/recovery reporting. `/adam:status` should distinguish pending/running/completed/failed work, expose the target/last-completed state and retain useful timings without raw content or unbounded history.
- Shutdown must have a bounded, documented policy for final work, cancellation and driver/worker cleanup. Do not hang Pi indefinitely; request cancellation/termination before closure and fence stale writes. Unfinished work must remain recoverable.
- Keep explicit import/repair command semantics deliberate; normal-hook detachment does not silently turn confirmed explicit operations into fire-and-forget commands. Do not widen notification-worker lease scope to ordinary Pi replication.
