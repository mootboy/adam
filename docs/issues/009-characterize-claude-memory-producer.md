# Characterize the reference Claude memory producer

> *This was generated by AI during triage.*

- Status: done
- Created: 2026-09-30
- Owner: unassigned

## Problem

Adam 0.4.0 plans to accept producer-owned memory sidecars, but the reference Claude producer's model invocation, credentials, detached lifecycle, checkpoint ownership, privacy boundary, and scheduling have not been characterized. Choosing those mechanisms by assumption could reintroduce blocking hooks, recursive plugin execution, duplicate generation, or undisclosed background model use.

## Outcome

An evidence-based producer contract establishes whether and how a fast Claude hook can enqueue work for a detached model-calling worker, which credentials and isolation flags it needs, what source locators it receives, how it recovers committed progress, and what consent and cost controls implementation must expose.

## Scope

### Included

- Controlled Claude Code hook environment and payload inspection without retaining prompt content or credentials.
- Detached-worker survival after the invoking Claude process exits.
- A bounded model invocation from the detached worker with hooks and project customizations disabled.
- Parent and subagent locator/checkpoint ownership.
- Crash-window, retry, cancellation, token-budget, and reflection-scheduling decisions.
- Privacy and explicit-consent requirements for background generation.

### Excluded

- Production producer implementation.
- Memory protocol fixtures or Adam sidecar ingestion.
- Neo4j schema or projection changes.
- Package-version changes or a 0.4.0 release.

## Acceptance criteria

- [x] Hook-visible locators and relevant environment capabilities are recorded without secret values.
- [x] A lifecycle hook returns without waiting for model generation.
- [x] A detached worker is observed running after the invoking Claude process exits.
- [x] A bounded model call succeeds or its credential requirement is identified without recursively loading producer hooks.
- [x] Parent/subagent source-checkpoint ownership and recovery are decided.
- [x] The append/checkpoint crash window has a concrete replay rule.
- [x] Model, token/cost, retry/cancellation, privacy/consent, and reflection scheduling are decided.
- [x] Findings are reflected in the 0.4.0 plan or its protocol-contract follow-up.

## Validation

Claude Code 2.1.285 was exercised with a disposable plugin under `/tmp/adam-producer-probe`. A non-interactive parent emitted `SessionStart`, `Stop`, and `SessionEnd` with source-session and absolute transcript/cwd locators. Hook environment checks found `CLAUDECODE` and `CLAUDE_PLUGIN_ROOT` but no API-key or OAuth-token values.

The `SessionEnd` hook detached a worker and returned. After 1.5 seconds the worker verified that the invoking Claude process had exited, then completed a safe-mode Haiku request in approximately 2.4 seconds using the existing Claude login. No recursive probe hooks ran. A JSON-schema request returned validated structured output and reported USD 0.0078702 usage; a separate USD 0.02 budget probe stopped with `error_max_budget_usd` only after reporting USD 0.030358, proving that the CLI budget is not a strict spending cap. `--bare` without an explicit API key failed as documented.

The resulting contract is [`../claude-memory-producer-contract.md`](../claude-memory-producer-contract.md). A content-free repeatable probe is committed under `test/fixtures/claude-producer-probe-plugin` and runs through `ADAM_TEST_CLAUDE=1 npm run test:claude`; no raw transcript, credential value, private prompt, or probe output is committed.
