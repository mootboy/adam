# Isolate live-test identities and restrict cleanup to test-created sessions

- Status: done
- Category: bug
- Priority: critical
- Created: 2026-10-02
- Owner: unassigned

## Problem

Production incident reported by the Claude agent: only eight AdamSession nodes remain, while 115 session identities survive in 69,876 orphaned entries; transcript streams and memories lost session ownership. The suspected destructive path is the packaged worker live test adopting the real Pi identity through host-state fallback, then deleting every session owned by that user in teardown. XDG isolation alone does not isolate legacy identity adoption.

Current main already overrides PI_CODING_AGENT_DIR in the primary connected worker environment, but the unavailable/hook environments and interactive plugin tests do not consistently isolate it; user-wide worker cleanup remains. Canonical repository cleanup also needs scrutiny because repository identities are shared across users.

## Outcome

Every test-launched Adam hook/worker/plugin has isolated canonical and legacy identity/state roots. Teardown cannot delete sessions outside explicitly recorded test-created IDs, even if identity isolation regresses.

## Scope

### Included

- Isolate PI_CODING_AGENT_DIR and all XDG roots for subprocess tests; remove inherited production Neo4j configuration unless a test deliberately uses its ephemeral test endpoint.
- Seed an independently generated fixture identity and assert worker state matches it, never deriving teardown scope from a potentially adopted runtime identity.
- Replace user-wide worker teardown with exact registered session IDs and narrowly owned child records; protect unrelated sessions and shared canonical code nodes.
- Audit live fixtures for shared repository identity and cleanup collisions.
- Deterministic isolation/cleanup regressions and ephemeral-only live validation, including unrelated-session sentinels.

### Excluded

- Production graph access, deletion, migration, or recovery.
- Killing the stuck installed worker or draining production queues.
- Producer implementation or release changes.

## Acceptance criteria

- [x] Hook/live subprocesses cannot adopt a user's real Pi state or inherit production backend settings.
- [x] Loaded identity is checked against an independently seeded test UUID before destructive cleanup; cleanup never trusts runtime-loaded user identity.
- [x] Exact test-created session cleanup preserves unrelated sessions of the same user and another user, their raw records, streams and memory relationships.
- [x] Shared repositories/files remain untouched by worker teardown; live repository fixtures use unique origins when deleting canonical nodes.
- [x] Missing/failed test state cannot broaden deletion scope; cleanup errors remain visible.
- [x] Deterministic and fresh ephemeral Neo4j suites pass without contacting localhost:7687.
