# Remember Adam connection settings and configure them inside Pi

- Status: in-progress
- Created: 2026-11-18
- Owner: unassigned
- Category: enhancement
- Target: 0.5.4
- Authorization: user subsequently approved implementation for 0.5.4. Merge, tagging, installation and production connection tests remain user-controlled.

As an Adam user, I want to configure my database connection once and have it available in later sessions, without remembering to export environment variables each time.

## Problem

Adam currently reads its Neo4j connection settings from environment variables. Forgetting to set them before launching a host leaves Adam unconfigured. Adam already uses a host-neutral user configuration directory, but does not load connection settings from it.

## Before → after

Illustrative workflow:

- Before: launch Pi in a fresh shell, discover Adam is unconfigured, then export connection variables and restart.
- After: run `/adam:configure`, enter connection settings, optionally test them, and explicitly save. Restart Pi; subsequent launches load the saved connection automatically.

## Outcome

Add a separate connection configuration file under `${XDG_CONFIG_HOME:-~/.config}/adam/`, shared by Pi, Claude MCP, and detached workers, plus interactive Pi setup. Keep connection settings separate from derivation recipes and permanent identity. Initially, saving requires restart to apply; hot reconnect is not included.

## Details

### Scope — included

- Automatic startup loading from a user-wide connection file, independent of the working repository.
- URI, username, password and optional database settings.
- Explicit environment configuration overrides the saved connection as a unit. Any present key selects environment-only settings; incomplete values disable connectivity rather than combine credentials from different connections.
- A proposed `/adam:configure` command with masked password entry and explicit Test connection and Save actions.
- Private, atomic persistence with file/directory sync and sanitized pre-/post-publication errors.
- Consistent loading across Pi, Claude MCP, and detached workers, including clear restart guidance.

### Scope — excluded

- Merge, tagging, installation or production activity without separate approval.
- Changes to the Adam skill or cross-session knowledge-transfer behavior.
- Credentials in `derivations.yaml`, identity changes, or repository-local connection overrides.
- Provider-auth integration or storing Neo4j credentials in Pi's `auth.json`.
- Hot reconnect, automatic production connection tests, schema setup, repair, or derivation generation during configuration.

### Security and configuration decisions

- Use a closed version-1 YAML 1.2 mapping in `connection.yaml`, separate from `config.json` identity and `derivations.yaml` recipes. Reject duplicate keys, aliases and parser warnings; keep passwords as literal strings. Core identity conversion is a separate [issue 038](038-use-yaml-for-core-identity-configuration.md).
- Initial storage uses an explicitly saved private plaintext password; no secret-manager references or command execution in 0.5.4.
- Linux/macOS only for saved credentials: owned private Adam directory/file, non-writable-by-others XDG root, no-follow regular-file reads and a single hard link. Existing invalid/unsafe files require manual repair before replacement. Reads are bounded to 64 KiB and strict UTF-8.
- Any present `ADAM_NEO4J_*` key, including empty, selects the whole environment connection without file fallback. Partial required values disable Neo4j. Normal test processes isolate XDG roots; source tests selecting environment settings cannot inherit missing values from the file.
- Terminal-only custom UI uses Pi's existing peer TUI Input for editing, without ever calling its plaintext renderer. Only an entered/empty indicator is rendered. Command arguments, ordinary chat prompts and session-entry APIs are not used for credentials.
- Keep credentials out of tool arguments/results, prompts, logs, diagnostics, recipe fingerprints and saved derivation metadata. Masked UI does not protect against other trusted code running with the same OS permissions.
- An explicit connection test must not perform schema initialization, migrations, synchronization, repair or model calls. Cancellation or failure leaves existing saved settings untouched. Cancellation settles independently of query/cleanup; request driver close without awaiting session RESET so active sockets are closed even if the peer stalls.
- Require TLS for routed Neo4j URIs, including loopback seeds. Unencrypted direct Bolt is restricted to actual loopback IPs or localhost, not DNS names beginning with `127.`.

### Acceptance criteria

- [x] With no environment connection configured, each supported host loads the same saved user-wide connection on startup.
- [x] Explicit environment configuration selects a coherent connection; partial settings follow a documented fail-safe rule rather than mixing sources.
- [x] Missing settings leave Adam visibly unconfigured without preventing Pi from loading; invalid/unreadable settings produce sanitized, actionable diagnostics.
- [x] Pi setup supports editing connection settings, masked password entry, explicit connection testing and explicit saving; secrets are absent from session history and ordinary output.
- [x] Cancelling setup/testing or a pre-publication save failure preserves the previous file; successful persistence is atomic, owner-only and file/directory-synced. Post-rename failures explicitly report publication with unconfirmed durability instead of claiming nothing was saved.
- [x] Saving clearly states that restart is required and does not disrupt the current connection or active work.
- [x] Invalid derivation recipes do not prevent connection loading, and connection secrets never enter the derivation data pipeline.
- [x] Automated tests use isolated configuration roots and synthetic credentials; normal tests require neither Neo4j nor a secret manager.
- [x] Documentation explains file location, environment precedence, security limitations and restart behavior.
