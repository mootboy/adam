# Use YAML for core identity configuration

- Status: proposed
- Created: 2026-11-18
- Owner: unassigned
- Category: enhancement

As an Adam maintainer, I want the user-wide configuration files to use the same format so inspecting and documenting them does not require switching between YAML and JSON.

## Problem

Connection settings and derivation recipes use YAML, but the core file that retains the user's permanent identity still uses JSON. Changing that file must not accidentally create a new identity or disconnect existing memories from their owner.

## Before → after

Illustrative configuration directory:

- Before: `connection.yaml`, `derivations.yaml`, and `config.json`.
- After: `connection.yaml`, `derivations.yaml`, and `config.yaml`, with the same permanent user UUID.

**Proposed change:** convert core identity persistence to YAML in a separate change, after agreeing the migration and conflicting-file policy. This is not part of 0.5.4 connection setup.

## Details

### Outcome and scope

- Change the canonical core identity format and update all host readers/writers and documentation.
- Preserve the permanent user UUID, atomic concurrent creation, private persistence and existing cross-host identity adoption/conflict behavior.
- Decide how existing JSON state is adopted and how simultaneous JSON/YAML files are handled before implementation; never silently select a different UUID or regenerate one after a parse failure.
- Keep credentials in the separate private connection file. No graph identifier changes, account merges or derivation recipe changes.

### Acceptance criteria

- [ ] An installation with existing core state retains exactly the same UUID after conversion and across supported hosts.
- [ ] Fresh/concurrent initialization creates one stable identity using the agreed YAML format.
- [ ] Malformed, unreadable and conflicting state fails visibly without replacing the permanent identity.
- [ ] Isolated interface tests and updated configuration documentation cover the approved migration policy.
- [ ] `npm test` passes and rebuilt packaged artifacts are committed.

### Validation

Not implemented. Current identity persistence is in `src/adam/replica/state.cljs`; changing it requires interface-level migration and concurrency tests using isolated roots, not real user identity files.
