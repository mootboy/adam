## Outcome

A testable, storage-neutral ClojureScript core prepares authorized model requests and validates completed derivation candidates before graph/Pi integration. Pin safe YAML, structured refresh/read selectors, source-occasion counting, dependency roles, snapshots/identities, budgets, cache reuse and freshness.

## Scope

Two modules under `src/adam/derivation/`: configuration and the cohesive refresh/read core. Clojure specs live beside their consumers; selection and role accumulation are immutable, source reads occur up front and candidate publication is deferred to the storage stage. YAML is a direct locked syntax-parser dependency. Fake callbacks supply model capabilities, full-request measurement, executor output and input snapshots; no real model, registry/auth store, Neo4j, host command/tool or background scheduling is invoked.

Native source-anchor extraction and provider tokenization certification are explicit later integration requirements. Source grants/ownership come from trusted injected graph snapshots, never memory prose or caller identity claims.

## Acceptance

- [x] Named YAML defaults/overrides; reject unknown fields, duplicate keys, aliases/tags, invalid limits, disabled support validation and missing model fields without echoing secret content.
- [x] Equivalent Git remotes normalize; source-scoped session IDs; one filter; language uses linked paths only; bounded read/history schema.
- [x] Direct grants authorize before selection, never reverse/transitively propagate. Reflection supports and comparison dependencies are complete; unresolvable comparison is omitted visibly, not leaked.
- [x] Repeated source occasions strengthen inference within one session; duplicate summaries/reflections do not manufacture independent evidence. Comparison inheritance does not contribute new source support.
- [x] Full separate payload is measured with output/provider headroom; oversized/invalid budgets and wrong explicit models make zero executor calls.
- [x] One fake call yields validated provider/model-bearing run, separate conclusion IDs, configuration/effective-limit snapshots and dependency hashes/roles; incomplete/unfounded/truncated output is rejected.
- [x] Empty results cache; input ordering is stable; model changes affect refresh reuse but not read freshness; missing/revoked evidence is unavailable; changed in-flight inputs can yield a latest-but-outdated candidate without retries.
- [x] Named/all-config refresh is sequential and isolates failures; timeout aborts the one call; raw executor errors do not enter outcome diagnostics.
- [x] Full release-build, deterministic/Node/package and clean generated-runtime validation; no live DB/model required or authorized.
